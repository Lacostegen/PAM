# Совместная работа через GitHub

## Рекомендуемая схема

- `main` - стабильная рабочая версия.
- `feature/...` - новая функция.
- `fix/...` - исправление ошибки.
- `docs/...` - документация.

Изменения попадают в `main` только через Pull Request.

## Настройки GitHub, которые стоит включить

В настройках репозитория желательно включить защиту ветки `main`:

- запретить прямой push в `main`;
- требовать Pull Request перед слиянием;
- требовать хотя бы одного проверяющего;
- требовать успешную сборку, если позже будет настроен GitHub Actions.

## Как принять изменения от другого человека

1. Открыть Pull Request.
2. Посмотреть список измененных файлов.
3. Проверить, что нет моделей, `bin/`, `obj/`, `.vs/`.
4. Склонировать ветку или проверить ее локально.
5. Запустить сборку.
6. Если все нормально, нажать Merge.

## Если два человека изменили один файл

GitHub покажет конфликт. Его нужно решить вручную:

```powershell
git checkout main
git pull
git checkout feature/name-of-change
git merge main
```

После исправления конфликтов:

```powershell
git add .
git commit -m "Resolve merge conflicts"
git push
```
